# TOEIC 850点・大学編入 学習管理

既存の学習チェックリスト・週別計画・模試記録・単語帳・フラッシュカードを引き継ぐ静的Webアプリです。TOEIC現在735点（L390/R345）から850点以上、2026年12月6日受験を前提とした計画を保持しています。クラウド同期や認証は導入していません。

## 起動

アプリ本体にビルドやパッケージ導入は不要です。Python 3でHTTP配信します。

```sh
cd /workspace/toeic-transfer-study
python -m http.server 8000 --bind 127.0.0.1 --directory /workspace
```

配信先のパスは `/toeic-transfer-study/` です。HTMLのダブルクリックでは辞書のfetchがブラウザに制限されるため、通常の利用はHTTP(S)で行ってください。各クラウドタスクは既に隔離されています。ユーザーの指定なしにGit worktreeを作らず、既存のチェックアウトを使います。

## 既存データの移行：必ず元の画面で先にバックアップ

ブラウザのlocalStorageはGitHubやHTMLに含まれません。ファイルをコピーしただけでは、別のURL・ブラウザ・端末へデータは移りません。公開してもPCとスマートフォンは自動同期されません。

1. **以前使っていた元のHTMLを、同じ端末・同じブラウザ・同じ場所で開く。** 元ファイルの移動・改名、ブラウザデータの削除は先に行わないでください。
2. 「進捗＋単語帳をバックアップ（JSON）」で全体JSONを保存する。念のため「単語帳のバックアップ」も保存する。ダウンロードしたファイルの存在と内容（checks、scores、vocabulary）を確認する。
3. 元HTMLとJSONを別の安全な場所にも保管する。JSONは個人の記録なのでGitHubにはアップロードしない。
4. 新アプリ／GitHub Pagesを開いて「バックアップを読み込む」を選択する。統合内容と競合件数を確認し、了承したときだけ読み込む。
5. 単語数、単語の意味、復習状態、科目別・週別チェック、模試スコアを比較する。再読み込み後も維持されていることを確かめる。確認後も元のファイルとJSONを残す。
6. スマートフォンへはJSONを安全な方法で渡し、スマートフォンのアプリ画面で同様に読み込む。

`file:` の保存範囲はブラウザによって異なります。空の元HTMLを別の場所から開いても、元データが消えたとは限りません。元の場所とブラウザで確認してください。実際の個人データの移行はユーザーのブラウザ上で必要です。この開発環境からはアクセスしていません。

## 保存の互換性と保護

既存のキー・基本形式を維持します。

- `kosen-transfer-study-2028-v1`: `{checks, scores, updated, ...既存属性}`
- `kosen-toeic-vocabulary-2028-v1`: `[{id, en, ja, box, due, missed, created, ...既存属性}]`

チェックID203項目と週別ID67項目、復習間隔1/3/7/14/30日・苦手10分後を維持します。未使用のチェックID、単語の追加属性も勝手に削りません。既存単語の件数上限・文字列切り詰め・重複英語の除去は読み込み時に行いません。不正な構造・重複IDは削除補正せず、保存停止と元データの救出を案内します。元アプリには各復習日時の履歴はなく、box/due/missedが復習情報です。追加属性として履歴があれば保持します。

最初の書き込み前には元の2キーの文字列を `kosen-study-before-upgrade-v1` にそのまま保管します。読み込み時だけでは書き込みません。インポート前は全体JSONのダウンロードを開始し、`kosen-study-before-import-v1` にも直前の元文字列を保管します。保管に失敗した場合は変更を中止します。ブラウザによるダウンロードの保存完了はアプリから保証できないため、ファイルを確認してください。

複数キーへの書き込みには復旧記録 `kosen-study-pending-write-v1` を使用します。保存失敗時は元の文字列に戻し、戻せない場合は保存を停止して次回読み込み時に復旧します。保存が全件完了していれば、その結果を採用します。別画面による変更を検出した場合は古い状態から上書きしません。

localStorageには複数タブ間の原子的なトランザクションはありません。同時編集を避け、同じ端末では1画面で操作してください。ブラウザによる保存領域の削除、端末故障、プライベートブラウズ終了に備え、端末外のJSONも定期的に残してください。

読み込み失敗時には通常の保存・インポートを停止します。「保存領域をそのまま救出（JSON）」は読める元文字列・保管コピー・復旧記録を書き出します。手動で保存領域を削除せず、まず救出ファイルを保管してください。不正な救出ファイルを強制的に上書き復元する機能は設けていません。正常な旧JSONから別の安全なブラウザ領域へ復元するか、元の文字列を保全したうえで個別に調査します。

## JSONの統合規則

既存の全体形式 `kosen-2028-checklist`（version 1〜3）、単語形式 `kosen-toeic-vocab`（version 1）、旧単語データの `cards` / `vocabulary`、正常な保存領域救出JSONを受け付けます。未知の形式・将来のバージョン・不正なレコードは、部分的に捨てず全体を拒否します。

- チェックは完了済みを優先する和集合。未チェックに戻す目的の同期には使えません。
- 模試は空いている記録だけを追加し、競合は現在の値を維持。
- 単語は前後空白と大文字小文字を無視して照合し、新しい単語だけ追加。
- 同じ単語の意味・復習状態が違う場合は現在の単語全体を維持。どちらが正しいか推定しません。取り込み元JSONを残し、必要なら画面から意味を編集してください。
- 新規単語のIDが現在の別単語とぶつかる場合は、新規側のIDを付け直す。
- インポート元の配列内でID自体が重複している場合は、破損の可能性があるため拒否する。

この方式は端末間の削除や変更を完全同期するものではありません。保存アダプターを画面から分離しており、将来の同期機能の追加時に拡張できます。

## 翻訳

1. 内蔵TOEIC辞書の完全一致。
2. 同梱EJDictの完全一致、次に原形候補（内蔵辞書も参照）。推定原形は画面に明示。
3. 見つからない語句はMyMemoryの英日翻訳。外部へ送るのは入力した英語です。

大文字・小文字、カンマと空白を伴う別見出し、複数形、規則活用・代表的な不規則活用に対応。語形推定や外部翻訳は完全な意味解析ではありません。必ず確認・編集して「この内容で単語帳に追加」を押してください。Enterと翻訳完了では保存しません。検索中の入力変更・手動編集を優先し、古いリクエストを中止します。

通信エラー、時間切れ、利用制限、無効な訳は画面に表示し、再検索・手入力ができます。CORSと一般的なネットワーク失敗はブラウザから区別できないため、通信制限として案内します。MyMemoryはAPIキー不要ですが、外部サービスの稼働・利用上限・CORS方針には依存します。

EJDictはCC0、上流リポジトリ `kujirahand/EJDict` のコミット `9663055d59a8cb1a35078a71db7a09ff39305828` を同梱。出典・ライセンス・SHA256は `assets/ejdict/` に保存しています。IndexedDBのキャッシュは同梱辞書の版ごとに分離し、キャッシュ障害時は同梱ファイルを使います。アプリ全体のオフライン起動は保証していません。

## 構成

- `index.html` / `css/style.css`: 元の画面・デザインとレスポンシブ配置
- `js/data.js`: 既存学習計画・チェック項目・内蔵辞書
- `js/storage.js`: 保存・検証・復旧・JSON解析・統合
- `js/translation.js`: 辞書・原形候補・外部翻訳・キャッシュ
- `js/app.js`: 学習進捗・模試
- `js/vocabulary.js`: 単語帳・フラッシュカード
- `js/backup.js`: バックアップとインポートの操作
- `backups/original.html`: 添付元HTMLの無変更コピー（SHA256付き）
- `tests/`: 合成データによる自動テスト

## テスト

```sh
cd /workspace/toeic-transfer-study
node --test tests/storage.test.cjs
# 上記HTTPサーバーを起動した状態。テストにはPython PlaywrightとChromiumが必要。

```

ブラウザテストは一時的な独立プロファイルを使い、個人の学習記録には接触しません。外部APIの成功・失敗・利用制限・入力競合は模擬応答を使います。実通信と区別した結果は `TEST_RESULTS.md` を参照してください。

## GitHub Pages

フェーズ3の実施はユーザー承認済みです。既存の `tamaki73/toeic-transfer-study` のmainを公開対象にし、`188cm-run` は操作しません。最新の公開状況・残る作業は `DEPLOYMENT.md` を参照してください。

Pagesの設定は「Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: main → /(root) → Save」です。公開先を別アプリからコピーせず、GitHubが表示するURLで確認してください。アプリ資産は相対パスで、`/toeic-transfer-study/` 配信に対応します。`.nojekyll` によりビルド不要の静的ファイルとして配信します。

公開後にCSS/JS/辞書のHTTP応答、翻訳、保存・復元、PC/スマートフォンで再確認します。ホスト名が同じPagesアプリ同士ではlocalStorageの保存領域を共有するため、同じキーを使う別アプリを同時利用しないでください。元のローカルHTMLからは自動移行されないので、上記JSON手順で移行します。
